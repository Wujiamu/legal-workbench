# 本地法律工作台全流程端到端真实验收（SOP）

本规程用于指导独立验收 Agent 在**不触碰既有业务案件、不修改工作台源码及 `.env`**的前提下，使用 `acceptance_simulation/dossier/` 的全格式仿真案卷，在 `http://127.0.0.1:8765` 上逐项完成端到端真实操作与验收，并输出可复核的验收报告。

## 纪律与红线

1. **专案隔离**：首先用 `create-case`（或浏览器新建案件）创建标题含 `TEST-ONLY 仿真验收专案` 的独立案件，记录其 `case_id`。**严禁向任何已有非本次新建的案件写入、修改或删除任何记录**。
2. **如实报告，不得修代码或遮掩缺陷**：遇到报错、超时、排版异常、OCR 漏识或逻辑不符合预期时，**原样记录触发步骤、请求/报错原文、实际现象与页面截图**；不得擅自修改项目源码或绕过门禁强行凑通过。
3. **协同使用配套 Skill**：
   - `legal-workbench-cli`：命令行查询、检索、建提案与导审计包；
   - `nonstandard-table-script-sop`：阶段 6 处理非标多表头 CSV；
   - `chart-substantive-review`：阶段 9 执行对外图表实质盲审。

## 十阶段端到端验收清单

### 阶段 1 · 服务与只读基线检查
- 检查 `http://127.0.0.1:8765/` HTTP 200 可访问，案件工作表与跨案期限时间轴正常渲染。
- 执行 `list-cases --limit 0` 与 `check-consistency`，确认 `ok: true`、`issues: []`。

### 阶段 2 · 建案与全格式 10 份材料上传解析
- 新建独立案件 `TEST-ONLY 华辰智造诉启航建工仿真验收案`。
- 通过网页上传（或同源 `POST /api/v1/cases/{case_id}/intakes/upload` 携带 `Origin: http://127.0.0.1:8765`）导入 `acceptance_simulation/dossier/` 全部 **10 份**文件，保留相对路径。
- 等待后台 worker 解析完毕，核对每份材料状态：
  - `01..05`、`07..09` 须全部解析成功（`03_最高额连带责任保证函（扫描件）.pdf` 与 `07_催款函与签收回执（拍照件）.png` 验证离线 RapidOCR 识别内容）；
  - `06_非标银行对账单_多表头混列.csv` 因格式非文本/XLSX 停留在未解析或不支持格式（正常，后续交由脚本规程与表格导入处理）；
  - `10_损坏扫描附件（模拟损坏）.pdf` 须被安全标记失败，不得拖垮同批其余材料或导致 worker 崩溃。

### 阶段 3 · 全案检索、原件/PDF 页图预览与人工标注复核
- 测试四种检索模式：`literal`（关键词如`最高额连带责任`）、`identifier`（信用代码/合同号 `HC-2025-EQ-0108`）、`amount`（CNY `8500000` / USD `50000` 与精确匹配不串币种）、`date`（`2025-03-10`）。
- 点开命中跳转 `SourcePreview`，验证 PDF 固定页预览（第 2 页）、扫描 PDF 预览、PNG 原图预览与 `read-source` 上下文定位一致性。
- 提交至少 1 条人工标注或 CLI/MCP Agent 标注并由网页端完成人工复核（确认正文与历史记录）。

### 阶段 4 · 办理信息、办案进度树、工时与跨案期限时间轴
- 为本验收案登记 3 条办理期限（如起诉状建议的 `2026-12-05`、`2026-12-18`、`2027-01-15`），回首页核对**跨案期限时间轴**准确显示。
- 进入办案进度页：核对默认实例化进度树、切换大纲/图形视图验证零重叠、测试新建工作节点、插入二审模板片段、关联材料、用 CLI 提交一条待确认提案并在网页执行确认或撤回（`⌘Z` 撤销验证）。
- 点击「工时」弹窗：测试启动/停止计时器（按 0.25h 向上取整）与补录 0.25 小时倍数工时及按标题汇总。

### 阶段 5 · 证据目录草稿导入与正式编号解析
- 参照 `09_证据目录清单草稿.xlsx` 建立证据分组并导入 8 条证据条目，完成材料页码绑定与逐条人工确认，记录确认后生成的正式证据编号（供阶段 7 与阶段 9 联动校验）。

### 阶段 6 · 候选主体消歧台、标准 XLSX 列映射与非标 CSV 外部脚本规程
- 在关系图工作区打开「候选主体消歧台」，运行扫描并核对是否正确抽取`上海华辰智能制造有限公司`（简称`华辰智造`）、`苏州启航建设工程有限公司`（简称`启航建工`）、`江苏宏信商业保理有限公司`（简称`宏信保理`）等主体与别名；将其合并/新建为主体及别名。
- 打开「表格列映射出边」上传 `05_标准往来明细台账.xlsx`，映射列并预览：核对按 `Decimal` 整数分汇总（CNY 与 USD 分开，含退回方向）及第 9 行`待银行回单确认`进入 `skipped_rows` 而不静默丢弃；提交写入关系图。
- 对 `06_非标银行对账单_多表头混列.csv` 严格按 **`nonstandard-table-script-sop`** 技能执行：只读前 20 行确认表头 → 编写透明本地 Python 脚本用 `Decimal` 汇总全量 25 笔有效流水＋异常行 → 调用 `save-analysis` 将脚本与汇总表留痕 → 按幂等 `request-key` 写入工作台待确认提案并确认部分边。

### 阶段 7 · 共现秒查、阅卷一键入图、防漏强指纹审计与自动排版
- 验证**双主体全案共现秒查**：同时选中`苏州启航建设工程有限公司`与`上海华辰智能制造有限公司`，确认命中 `08_工商变更与关联核查底档.txt` 中仅含简称「启航建工与华辰智造」的对账段落，并带出同段 `8,500,000.00` 与 `2025年9月18日` 精确值；点击「挂为出处」或「送入关系图」生效。
- 打开**防漏审计抽屉与案卷健康格子图**：
  - 核对材料覆盖分类与格子图点击筛选（含已引用、已解析未引用、损坏失败 `10_损坏...pdf`、未解析 `.csv`）；
  - 核对**孤儿机构差集**：发现尚未入图的高频机构（如`南京鼎盛重工科技有限公司`、按入图情况的`苏州鑫悦贸易有限公司`）；
  - 核对**强指纹碰撞**：准确检出跨文档手机号 `13918826655`、邮箱 `legal.contract@huachen-sim.example`、银行账号 `6225880123456789012`、启航建工信用代码，同时确认主合同中的 18 位身份证号与物流单号 `9000123456789012` **未**误报。
- 执行自动排版（`stress` / `layered`）并刷新页面确认坐标持久化生效（无 404）。

### 阶段 8 · 诉请金额管理与瀑布图
- 按 `01_民事起诉状.docx` 建立「主诉请请求组」（计入全案总计：`8,500,000.00` 本金 + `637,500.00` 违约金 + `180,000.00` + `12,800.00` 费用 + `-300,000.00` 保证金抵扣 = 净额 `9,030,300.00` 元）与「替代利息分组」（不计入全案总计：`510,000.00` 元）。
- 验证全案总计严格按整数分汇总且不把替代利息重复累加。

### 阶段 9 · 一源三态导出、硬门禁拦截与外部实质复核
- 在关系图与诉请金额分别测试三态导出（`working`、`client`、`court`）：
  - 刻意保留 1 条 `pending` 提案或 `suspected` 边或无出处边，验证 `court` 硬门禁返回 `blocker` 并阻断默认导出；
  - 对含内部备注、`pending` 提案、`ruled_out` 边的图形导出 `client` / `court` 版 SVG 与 Markdown/CSV《图示引用索引附表》，核对零泄漏与编号与阶段 5 证据目录 100% 一致。
- 冻结一张关系图快照后，刻意植入 3 类错误（① 金额放大如 850 万错标 8500 万或 600 万错标 6000 万；② 担保方向画反如 `华辰智造 → 宏信保理` 或 `启航建工 → 宏信保理`；③ `04_战略合作意向书（未生效）.txt` 关系标成 `evidenced` 已生效），运行 `export-chart-audit-bundle`，按 **`chart-substantive-review`** 规程独立盲审并核对能否全部检出。
- 验证浏览器 `760px` 半屏窄窗与中文输入法回车不误触发。

### 阶段 10 · 归档只读守卫与收尾验收报告
- 将本验收专案执行「结案归档」，验证：工作台首页默认隐藏、进度/材料/关系图写操作全部禁用且接口拒写、三态导出与防漏审计只读查看仍可用；随后执行「取消归档」恢复可写状态（或保留归档并标注清晰）。
- 运行 `check-consistency` 确认整库一致性 `ok: true`。
- 输出《端到端真实验收报告》：逐项列出阶段 1–10 实测证据、标准答案比对情况、截图/导出物清单及任何发现的缺陷或边界。
