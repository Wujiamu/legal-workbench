# 非标表格确定性算账规程（SOP · 通用版）

本规程不依赖任何软件或数据库。输入是一份或几份表格文件（银行流水、对账单、台账、微信/支付宝账单导出等），输出是**一份可复核的 Python 脚本、一份汇总表、一份异常跳行清单**，交承办人复核。

适用条件（命中任一即用本规程）：多行合并表头；借贷方向由符号或独立列表示且同一文件内不统一；多币种混列；一个文件含多期对账；摘要字段需要拆解成主体与事由；列名与顺序在不同期次之间漂移。

不适用：结构化单一表头的小表。那种情况直接读表即可，不必写脚本。

## 一、边界与红线

1. **涉密、涉个人隐私或当事人禁止上云的案卷，严禁接入云端模型。** 只在本机离线模型或纯脚本环境下处理。开始前先确认：这份材料能不能进入当前对话模型的上下文。
2. **严禁让模型肉眼扫描全表累加。** 可以在上下文里看 20 行样本，但不可以在上下文里"看着几百行算总数"——那既不可复核也无法重现。
3. **原始材料只读。** 脚本只读取原件，所有产物写到独立工作目录，不得覆盖或改写输入文件。
4. **金额一律以整数分计算。** 任何以浮点数参与金额运算的脚本视为不合格。
5. **不做法律判断。** 本规程只负责"数算对、口径说清、异常列全"；某笔款项是否属于本案争议范围，由承办人决定。

## 二、执行步骤

### 1. 先读样本，确认结构（只读，不计算）

读取前 20 行与工作表/分页清单，记录并在脚本注释中写死下列事实：

- 文件编码（UTF-8 / GB18030 / 带 BOM）与分隔符（CSV 需 `csv.Sniffer` 复核）；
- 表头实际占几行，哪一行是真正的列名，合并单元格展开后哪些列被重复填充；
- 日期格式（`2026-01-02`、`2026/1/2`、`20260102`、Excel 序列号）；
- 金额列是否带千分位、货币符号、括号表示负数、全角字符；
- 借贷/收支方向如何表示：独立列（借/贷、收入/支出）、符号、还是由"交易类型"推导；
- 币种是列、后缀还是混在同一列里；
- 明显的页脚/小计行、空行、重复表头行出现在哪个位置（这些必须被识别成本规程第 3 步的异常或跳过项）。

样本中出现的每一种形态，都要在脚本里有对应的处理分支；样本里没出现但全量可能出现的形态（如跨年、闰日、退款冲正），在脚本里显式写 `raise` 而不是猜。

### 2. 编写透明、确定性的 Python 脚本

硬性要求：

- **金额用 `decimal.Decimal` 解析，`ROUND_HALF_UP` 量化到 0.01 后乘以 100 转为整数分**，全程整数分相加；禁止 `float` 参与金额计算，禁止在求和后再四舍五入。
- 方向统一：把"借/贷"、"收/支"、正负号归一成 `+1 / -1`，并在汇总里同时给出"笔数"与"净额"，避免只给净额掩盖方向错误。
- 幂等：同一输入重复运行输出完全一致（排序稳定、不含时间戳作为键、不依赖字典插入顺序的随机性）。
- 无隐藏状态：脚本自包含，不读环境变量、不连数据库、不访问网络。
- 注释写清每一处"为什么这样解析"（尤其是表头偏移与方向判定），便于承办人逐行核对。

### 3. 异常行必须单独成表（`skipped_rows`）

任何一行只要出现下列情况，就写入 `skipped_rows` 并在汇总里给出计数，**不得静默跳过、不得当 0、不得用上一行补齐后当成正常行**：

- 金额无法解析（空、`--`、`/`、纯文字）；
- 日期无法解析或落在非法日期；
- 方向无法确定（借贷列同时为空，或符号与方向列矛盾）；
- 币种缺失或不在本次允许的币种集合内；
- 重复数据（同一流水号 + 金额 + 日期出现两次以上）；
- 判定为小计/页脚/重复表头的行。

每条记录至少包含：`file`、`row_no`（1-based，指向原始文件真实行号）、`raw`（原始行内容，脱敏时保留结构）、`reason`（固定枚举值，便于统计）。

### 4. 交付物

一次性交付四样东西，缺一不可：

1. **脚本文本**（可复核，能直接在同样输入上重跑）；
2. **汇总表**：按主体对/科目/期间分组，含总金额（分）、笔数、起止日期、原始行号范围；
3. **`skipped_rows` 明细与计数**：计数必须与"原始总行数 − 已计入行数"严格相等，不等就说明脚本有漏；
4. **口径说明**：一行一句话，写清本次算账的时间范围、币种、方向定义与去重规则。

交付时明确写出"以上结果由脚本算出，待承办人复核"，不要把脚本输出表述为已核实的法律事实。

## 三、自检清单（交付前逐条过）

- [ ] 汇总净额 = 所有已计入行按方向求和，且与脚本内的断言一致；
- [ ] 已计入笔数 + `skipped_rows` 条数 = 原始数据行数（不含表头）；
- [ ] 抽 5 笔（含最大额、最早、最晚、一笔退款、一笔跨期）人工核对与脚本结果一致；
- [ ] 脚本里没有 `float(` 、没有 `sum(...)` 后四舍五入、没有 `round()` 用于金额；
- [ ] 输出目录里没有覆盖任何输入文件。

## 可选：若已接入素章工作台

未接入素章时，以上四样交付物直接作为文件或对话内容交付即可，本规程到此结束。

若本机已装有素章（PlainFolio）工作台，并且承办人已在该案上授权：

1. 先由承办人在本机终端授权该案（默认 `deny_all`，未授权时任何读写都返回 `forbidden`，此时立即停止并请其授权，不得改走其他途径）；
2. 用 `save-analysis`（`statement_kind="agent_analysis"`）把脚本正文、汇总表与 `skipped_rows` 清单保存为本案留痕，并绑定源材料或片段出处；
3. 需要把主体与金额写入关系图或诉请金额时，走对应的幂等写入命令并携带唯一 `request_key`；写入一律进入**待确认**区，由承办人在界面上确认后才计入小计与总计；
4. 用完提醒承办人收回授权。

以上联动均为可选；不接入工作台时，本规程的执行标准与交付物不变。
