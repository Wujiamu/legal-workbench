# 对外图表实质复核（SOP）

本技能消费本地法律工作台 `export-chart-audit-bundle` 输出的只读审计包（JSON），承担程序硬门禁之外的法律实质与策略核验。复核全程保持只读，不替承办人改图、确认提案、豁免门禁或发送审计包。

## 授权前置与硬围栏纪律（必须先执行）

1. **禁止默认连接、探测或列举工作台**。即使对话里提到案卷，在用户明确授权前也不得调用 `list_cases`、`list-cases`、`search_case` 或任何带 `case_id` 的工具与命令。工作台默认 `deny_all`（全局锁死），未获授权时除 `list_cases(limit=0)` 连通探活外一律返回 `forbidden`。
2. **先向用户申请明确授权**，一次问清三件事：
   - 本次允许访问的**具体目标案件**（`case_id` 或案件名称）；
   - 当前所连接的对话模型**是否合规**接触该案材料——涉密、涉个人隐私或当事人禁止上云的案卷，**严禁**接入云端模型，只能用本机离线模型；
   - 请用户**本人在本机终端**执行 `scripts/lwb agent-grant <case_id>`（Windows 为 `scripts\lwb.cmd agent-grant <case_id>`；桌面安装包用 `<可执行文件> --run-cli agent-grant <case_id>`）临时放行该单案。授权只能由承办人本人执行，你不得代跑，也不得要求用户把命令交给你来执行。
3. **禁止绕过硬围栏**。若工具返回 `forbidden`（未获授权或处于 `deny_all`），立即停止该案的全部操作并如实告知用户「需由您在本机授权」。**严禁**改用 Shell / Python 直连数据库、读取 `var/data`、读取 `.env`、改写 `var/runtime/agent-access.json`，或改走 CLI / HTTP / 另一个客户端绕过门禁；这些做法一律视为越权。
4. **用完即锁**。任务结束回复用户时，提醒用户按需执行 `scripts/lwb agent-revoke <case_id>`（Windows 为 `scripts\lwb.cmd agent-revoke <case_id>`）收回该案权限，或执行 `scripts/lwb agent-lock` 全局锁死、收回全部权限。不要替用户判断「下次还要用，先留着」。

## 四步执行规程

1. **拉取审计包并确认基线**：
   - 以显式参数调用 CLI 或 MCP 工具 `export-chart-audit-bundle`（指定 `--case-id`、`--chart-type graph|claims`、`--target-id`、`--profile client|court`，关系图当庭版须同时指定 `--snapshot-id`）。
   - 核对 `chart_meta` 是否对应本次交付对象、模式、快照版本或 `frozen_at` / `digest`。
   - 原样抄录 `preflight.issues` 中的全部 `blocker` 与 `warning`，并在后续步骤中继续核对能取得的原文。

2. **逐条文图字面与数值核对**：
   - 逐条将 `assertions` 的 `display`、起止主体与方向（`from_entity_id` → `to_entity_id` / `directed`）、关系类型与可信状态（`kind`、`credibility`）、金额（`amount_cents` 整数分换算元与币种，不得丢失分位或差错数量级）、持股比例、日期区间，与每条出处所附 `sources[].context`、`context_before`、`context_after` 原文逐字比对。
   - 核查要点：主体全称与诉讼角色、动作与方向（如借款人/出借人、担保人/主债务人、付款/收款、股权上下游）、币种与单位（元 vs 万元）、金额分元换算、认缴与实缴、条件是否已成就。
   - 引用当前正式证据编号（`evidence_labels`）、页码或工作表定位与足以支撑判定的简短原句；原文缺失、截取不足或来源互相冲突的，一律标为「需核改」并注明须补核的原件或页码范围。

3. **证明力越界与诉讼策略自认核查**：
   - 检查每条断言的可信状态与定性是否超出所附材料证明力范围：例如单方陈述/律师函/备忘录/意向书/框架协议是否被误画成已生效或既定事实（`evidenced` 实线）、尚待查明事项是否被当成确定结论、保证人与主债务人主体是否混同、原件与转述件差别是否标明。
   - 若承办人同时提供同案起诉状、答辩状、代理词或已确认办案口径，逐项核对图表主张与文书口径是否矛盾，或是否存在不当自认风险；列明可能影响的诉请、抗辩或对外表述，交承办人拍板。

4. **交付结构化《复核问题清单》**：
   - 写明图表标题、版本/快照、导出模式、检查断言条数、程序预检阻断/告警、未能核实的项。
   - 按下表输出逐条结论，结论仅取「无异常」「需核改」「策略预警」；发现确定数值或方向差异时，必须写清**图上原值**与**原文应核正值**：

| 断言 ID 与图上表述 | 结论 | 证据编号、定位与原句 | 差异或策略影响 | 待核动作（交承办人） |
|---|---|---|---|---|

   - 在文末明确提醒：**本清单仅供核查参考，须由承办人终审并在工作台修正后重新预检再对外导出。**
