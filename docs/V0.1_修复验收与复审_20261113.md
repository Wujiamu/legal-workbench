# 法律工作台 V0.1 修复、验收与复审

2026-11-13，受检范围为当前项目目录。以[第六轮复审](V0.1_第六轮整改复审_20261113.md)的三项发现为起点，复核了共享导入路径、正常 worker 恢复和列表刷新。

| 验收项 | 实现与验证 |
|---|---|
| 上传失败清理 | 失败处理覆盖发布回读、审计和提交。回滚后在排他锁下核对已登记的路径，再清理无引用文件。三个故障点实测均无批次、任务或磁盘残留，原请求键可重试并完成解析。 |
| 备份期间的回滚 | 清理使用与备份相同的锁，等待备份释放锁后继续。用独立 PostgreSQL 连接控制锁和维护标志，确认清理等待、保留原完整性错误、持久化损坏标记，磁盘未留下无引用原件。此前另一批次先提交同路径的用例也通过。 |
| 导入共用原件与恢复 | 网页上传和目录导入使用同一套对象登记、去重和失败清理。两个入口在实际发布处并发时只存一份原件，两个任务均可完成解析。同请求键并行重试返回同一批次与任务。材料和解析任务在同一事务中提交，入队中断后由正常 worker 恢复。 |
| 迟到的列表刷新 | 保存回调触发当前分类和页码的刷新，旧请求响应无法覆盖当前列表。组件测试覆盖改名后切回、切换分类和翻页后的迟到响应。 |

完整回归为后端 **273 项**和前端 **27 项**。后端使用独立 PostgreSQL 18 和合成材料，配置指向的默认库保持 0 张公开表。类型检查通过，生产前端已重新构建。

备份恢复演练 **7/7**，恢复后原文和金额均可检索，一致性检查无问题。端到端数据和性能见 [T19 本轮实测](reports/T19-修复验收实测-20261113.md)。

本轮复审范围内未发现剩余阻断项。界面竞态用受控组件响应验证，浏览器手动交互和真实案件材料未复验。旧 22 条检索测试仍待原样本与预期结果。上传进程若被强杀，可能留下已写盘但未登记的文件，一致性检查可报告这类残留。本轮的上传故障注入覆盖可执行回滚清理的异常。
