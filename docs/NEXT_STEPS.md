## 已知限制（V0.1 明确不做）

| 限制 | 影响 | 说明 |
|---|---|---|
| 单用户、单机 | 不能多人协作 | 会话在进程内，重启即全部失效；没有用户表、没有权限分级 |
| 单 worker | 大批量导入只能串行 | `pg_try_advisory_lock` 保证全局唯一 worker；1000 文件约 2 分钟索引 |
| 无加密静态数据 | 磁盘被读取即可看到材料 | PostgreSQL 与 `var/data` 都是明文；依赖操作系统全盘加密（macOS FileVault / Windows BitLocker） |
| 备份不能阻止外部编辑 | 备份期间用 Word 改文件可能不一致 | 维护标志只挡本服务写入；需要绝对一致时先关闭其他软件 |
| 不自动清理孤立文件 | `check-consistency` 只报告 | `repair-consistency` 不删除、不猜测归属 |
| 恢复只能到空环境 | 不能增量或覆盖恢复 | 目标库必须无表、`DATA_ROOT` 必须为空 |
| 实机已验证平台 | 仅 macOS 实机验证 | Windows 10/11 已完成跨平台源码适配与模拟单测，待真实 Windows 宿主机按 [WINDOWS_CHECKLIST.md](WINDOWS_CHECKLIST.md) 实测；Linux 未测 |
| DOCX 嵌入图片不识别 | 图片里的文字查不到 | 只在 `warnings` 标注部分覆盖，不静默忽略 |
| 加密 Office 文件不支持 | 会报解析失败 | 未构造样本断言具体错误码 |

## 建议的下一步（按优先级）

1. **补齐 22 条原测试**。拿到样本后接入 `backend/tests/`，单独命名，逐条对照期望结果；不通过就修，不改成通过。
2. **真实材料小规模试用**。选一个已结案、有电子副本的案件，先导入 10–20 个文件，确认分类、检索、引用跳转符合实际工作习惯。首次导入前先做一次完整备份。
3. **备份策略落地**。目前备份是手动命令。建议加一条每日定时（`cron` 或 launchd 均可），备份到外部磁盘，并定期做一次恢复演练（`scripts/rehearse_backup_restore.py` 可复用）。
4. **OCR 质量评估**。当前用 PP-OCRv4 通用模型，未针对法律文书（印章、手写、复印件）调优。建议收集 20–30 份真实扫描件，人工核对识别率，再决定是否需要预处理（去噪、纠偏、二值化）。
5. **性能观察**。实测 1000 文件 / 10000 页检索 P95 415ms，单字扫描 545ms。案件规模到 5 万页以上时需重测，`scripts/run_acceptance.py` 的语料生成器可直接放大。
6. **Linux 支持**（如需要）。主要工作是 `scripts/lwb` 里的 `pg_ctl` 路径与权限处理，以及 OCR 字体回退。

## 运行反馈

- **2026-11-23 TEST-ONLY 实机验收缺陷已全部修复并正式应用。** 原验收暴露的 9 项缺陷（归档 MCP/CLI 标注与分析写穿透、标准 XLSX 多币种混币、表格拆列币种金额漏检、损坏 PDF 误归「不支持」、引证附表丢失 DOCX 段落定位、画布 `出处 undefined`、双向资金边标签重叠、归档界面写入口可展开、`save-analysis --content-file` 无法单独使用）已全部修复（零迁移），通过全量回归、两轮独立代码审查闭环及正式服务 `127.0.0.1:8765` 实机 API/CLI 与 Chromium 浏览器复测；同日进一步完成首页已归档切换、共享案件导航栏、进度大纲防重叠与关系图间距等 UI/UX 改进（前端 57 文件 407 项全过，待下次重启服务后做桌面/浏览器顺手复看）。历史已归档专案保留既有解析快照，未对解析类两项重跑覆盖，本地验收原件归档于本机 `docs/reports/`（不随开源仓库分发）。

- **网页进程仍监听时，数据库停止会阻塞桌面启动（2026-11-23 已修复）。** 原问题位于 `scripts/lwb-launch` 在 `running=True, ready=False` 时仅等待已有进程，未恢复数据库与已退出的解析 worker。现已为 `scripts/lwb` 新增 `start-db` 命令，并在 `scripts/lwb-launch` 中自动调用 `scripts/lwb start-db` 失败即报错（不再空等 45 秒），拉起后补启受 PostgreSQL advisory lock 守护的 `scripts/lwb worker`；已补齐 [test_lwb_launch.py](../backend/tests/test_lwb_launch.py) 4 项单测与 `scripts/lwb start-db` 本机幂等实测通过。

## 不该做的事

- 不要把这份工作台当作"法律结论生成器"。它做的是材料归档、检索定位、引用留存；分析正文由人或外部 Agent 写，`review_status` 只是标注，不证明观点正确。
- 不要在没有备份的情况下做批量重解析或批量改分类。
- 不要把 `.env`、`var/`、备份目录放进任何同步盘或版本库。
- 不要在未验证的规模上宣称性能达标。本项目的性能结论只对实测的 1000 文件 / 10000 页成立。
