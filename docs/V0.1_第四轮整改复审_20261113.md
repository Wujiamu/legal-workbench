# 法律工作台 V0.1 第四轮整改复审

2026-11-13。**上一轮四项原始复现均通过，当前版本暂不能签收。** 在同一批上传的失败处理、跨副本并行登记和切换材料时的保存响应中，复现了 1 项 P1 和 2 项 P2。

| 优先级 | 实测与原因 | 关闭标准 |
|---|---|---|
| P1 | **原件校验失败会提交半个上传批次，原请求键无法重试。** 先建立一个已登记对象，并在隔离存储中改动其文件字节。用同一批次上传一份新 TXT，再上传一份字节与已登记对象哈希相同的 TXT。第二项触发校验失败后，`create_upload_intake` 为保存 `integrity_error` 直接提交整个事务。新连接查到这次失败的批次已落库，含一条条目、零任务。用原请求键重试返回 `conflict`，提示「既有接收批次缺少任务记录」。[失败分支](../backend/src/legal_workbench/imports.py#L388) · [请求键复用](../backend/src/legal_workbench/imports.py#L346) | 明确失败批次的语义。若整批失败，撤销批次与条目，单独持久化原有对象的完整性标记，并处理本次发布的文件。若接受部分成功，提交可跟踪的任务和逐项状态。测试应核对请求键重试、任务和磁盘状态。 |
| P2 | **不同工作副本并行登记相同字节时，一次失败并留下无引用文件。** 对同一材料创建两份工作副本，分别编辑为相同内容。两个连接各持自己的 revision=0，让两个请求都完成物理发布后再执行数据库插入。实测一个成功，另一个抛 `uq_stored_objects_case_sha`，磁盘多出一份无引用的版本文件。工作副本 CAS 锁的是不同记录。写入 `StoredObject` 的 `flush` 位于异常清理范围之外。[副本 CAS](../backend/src/legal_workbench/materials.py#L180) · [发布与清理边界](../backend/src/legal_workbench/materials.py#L218) | 对不同副本的同内容登记统一处理对象竞争，保留独立版本和任务并复用同一对象。断言没有无引用文件。另保留同一工作副本、同一修订号只能成功一次的回归。 |
| P2 | **甲材料的迟到保存响应会改动乙详情。** 挂起甲的分类保存，切到乙并挂起乙的保存，再让甲返回 revision=1。受控组件测试观察到乙显示「分类已保存」、乙详情的修订号被替换、乙仍在保存时按钮已经重新可点。分类和改名的响应处理没有副本操作已有的归属检查。本轮运行的是分类路径。[保存处理](../frontend/src/components/MaterialDetail.tsx#L112) | 将分类和改名请求的修订号、提示、错误与忙碌状态绑定到发起操作的材料。验证乙操作进行时，甲的迟到成功或失败都不能改写乙的界面。 |
