## 3. 其余应复核事项

- **P2 · R04 指定页 OCR 会漏页却报完整。** [预先跳过](../backend/src/legal_workbench/parsing/pipeline.py#L286) 的集合包含没有 Segment 的页，[复用函数](../backend/src/legal_workbench/parsing/pipeline.py#L118) 遇到这类页直接返回 None。两页 PDF 实测：旧 run 为第 1 页 `no_text_detected`、第 2 页 `extracted`；仅对第 2 页强制 OCR 后，完整且已激活的新 run 只剩第 2 页，任务进度 1/2。保留空白页记录；对此前失败且无可复用结果的页明确保留失败或重新处理。已完成页在恢复时不重复 OCR 的常规回归通过。
- **P2 · OCR 超时错误分类不稳定。** [超时封装](../backend/src/legal_workbench/parsing/ocr.py#L40) 抛 `TimeoutError`，[PDF 处理](../backend/src/legal_workbench/parsing/pdf.py#L156) 只捕获该直接异常；本机 RapidOCR 的缩放路径会包装异常。补可重复的断言，保证真实超时按 `timeout` 报告，真实缩放错误仍单独报告。
- **P2 · T16、T17 还有计划缺口。** [上传面板](../frontend/src/components/UploadPanel.tsx#L34) 仅在组件状态保存任务 ID，刷新或收起面板不能继续跟踪；逐项状态只取 200 条，终态计数也基于这 200 条；重试沿用相同 job ID，首次终态已通知后，重试成功不会再次通知材料列表刷新。[检索页](../frontend/src/components/SearchPanel.tsx#L48) 仅把命中放在 React 状态，复制的是 UUID，未实现 `source_ref` 链接参数与刷新定位。以上为代码确认，未将既有浏览器交接当作这些场景的通过证据。
- **P3 · 备份清单 schema 标识漂移。** [`backup.py`](../backend/src/legal_workbench/backup.py#L31) 仍固定写 `0002`，当前迁移已是 `0003_audit_operation_check`。本轮恢复成功；清单中的版本不能用来识别实际迁移状态，宜随迁移版本生成或校验。
- **D1/D2/D3 审查。** D1 的同时间戳排序有稳定键；同前缀编号可用，不承诺通用自然排序，暂无必要增加持久化排序键。D2 的 TXT 直读预览有存储哈希检查、大小上限及 `text/plain`、`nosniff`、CSP，现有测试覆盖未解析预览；保留现有方案。D3 单批正常完成时 1.5 秒轮询和首次刷新测试通过，缺口是上述任务续看、计数和重试刷新，不需要先改成服务端推送。
