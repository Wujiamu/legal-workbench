# 主体关系图、证据目录与诉请金额模型

状态：2026-11-20 确立（P0）。适用范围见 [案件主体关系图](../changes/20261120-案件主体关系图.md) 与 [期限时间轴与诉请金额](../changes/20261120-期限时间轴与诉请金额.md)。与 [界面与 Agent 共用业务命令](20261116-界面与Agent共用业务命令.md) 和 [进度通用节点模型](20261116-进度通用节点模型.md) 配套适用。

## 问题

工作台要新增两项带可写数据结构的可视化能力（主体关系图与诉请金额构成），并支撑后续的案件事实时间线、资金流向图、证据—待证事实对照表。需要在一开始固定五项跨模块、以后很难调整的结构性边界：

1. 一案多图下，主体、关系与“图”是什么归属关系；布局坐标要不要入库。
2. 证据编号（如 `证据1-1`）存在哪里，如何随证据目录调整而自动更新，且不破坏历史快照。
3. 快照与“客户同意”如何防篡改，如何处理 Agent 待确认修改。
4. 新领域的变更记录是改写 `progress_changes`，还是按领域独立建表。
5. 诉请金额如何存储与分组，避免精度误差和正负号歧义。

## 可行选择与决定

### D1：主体、关系、出处属于案件级事实；图是视图投影，布局坐标按图持久化

- **放弃方案**：每张图各自存一份主体和关系。同一主体或关系在两张图里状态、别名、出处必然分叉，后续事实时间线、资金流向图也无法共用同一批主体。
- **决定**：
  - 主体（`case_entities`）、别名（`entity_aliases`）、关系（`case_relations`）、出处（`graph_sources`）属于**案件**，全案唯一维护；未来事实时间线、资金流向、证据对照表直接引用 `case_entities`。
  - 每张关系图（`relation_graphs`）是一个命名视图，记录纳入本图的主体与坐标（`relation_graph_nodes`）、纳入本图的关系（`relation_graph_edges`）和分组框（`relation_graph_groups`）。
  - **布局坐标持久化**：与办案进度（[K10/K13](20261116-进度通用节点模型.md) 不保存手动坐标）不同，关系图常含环路、多向交叉，自动布局（elkjs）只负责新节点初始落位和“重新自动排版”，人工拖拽后的 `(x, y)` 坐标按图入库。
  - “从本图移除”只删图内成员关系；“删除主体/关系”影响全案并软删除，操作前服务与界面均提示受影响的图数量。

### D2：证据目录是唯一编号来源；图与诉请只存稳定引用

- **放弃方案**：在关系或节点上直接手填或复制“证据1-1”字符串。目录增删调序后全图编号立即过期，且外部导入与人工维护难以统一。
- **决定**：
  - 本案证据目录（`evidence_groups`、`evidence_items`、`evidence_item_bindings`）是证据编号的唯一事实来源。编号按“组序 + 组内序”动态计算为 `证据{组}-{序}`（多页或片段命中时追加页码，如 `证据1-1 第5页`）。
  - 图的出处（`graph_sources`）与诉请出处只存不可变/稳定引用：`segment_id`（即 `source_ref`）、`material_id` 或 `annotation_id` 三选一，带 `(case_id, …)` 组合外键。
  - 展示工作稿时，由引用反查所属材料及页码，匹配已确认的目录绑定得到当前编号；未收入目录时显示材料名并标“未编号”。
  - 外部 Word/Excel 目录导入后，Agent 生成的目录条目及材料绑定进入待确认状态，**人工确认前不参与编号显示**。

### D3：快照不可变（冻结当时编号）；客户同意仅挂快照且追加留痕

- **放弃方案**：快照只保存版本号指针，打开时重放历史；或允许在工作稿上直接点“客户已同意”。前者一旦目录调序就看不出“客户当时看到的是哪个编号”，后者工作稿继续改动会使“同意”失去指向。
- **决定**：
  - 快照（`relation_graph_snapshots`）按单张图冻结，将冻结时的主体、别名、关系、出处、布局、分组以及**当时的证据编号**整体序列化为不可变 JSONB，记录阶段标签、说明与可选的进度节点引用。
  - 冻结时自动排除尚未确认的 Agent 变更；若有待确认项则向承办人提示数量，由人工选择先复核或不含待确认项继续冻结。
  - 查看快照时按冻结时编号展示；若现行目录编号已变化，旁注“现为证据 X-Y”。“恢复为工作稿”是一条普通人工写命令，写变更记录并可撤销，不改动原快照。
  - 客户同意（`snapshot_consents`）只能挂在快照上，字段含同意人、客户实际同意时间（可补录）、同意方式、来源说明、可选凭证材料、备注（前端占位提示“例如：客户部分同意”）与系统登记时间。记录不可修改，撤回或更正通过追加记录留痕。
  - 快照、恢复、客户同意、确认/撤回 Agent 变更**仅限人工入口**，MCP/CLI 不暴露这些命令。

### D4：变更记录按领域独立建表，共用 `case_change_seq` 与命令框架

- **放弃方案**：修改已验收的 `progress_changes` 表加 `domain` 列并改造其唯一约束与查询。该表刚通过五轮审查并已上线 8765，改动迁移面和回归风险不划算。
- **决定**：
  - 保持 `progress_changes` 原样不动。新领域各自建结构一致的变更表（`graph_changes`、`evidence_changes`、`claim_changes`），统一由共享服务工具模块提供锁、CAS、diff 记录、待确认/确认/撤回逻辑。
  - 复用已有的 `case_change_seq(case_id, domain)` 表，新增领域名 `graph`、`evidence`、`claims`，前端统一按现有 `GET /cases/{id}/changes/seq` 轮询检测 Agent 写入。

### D5：诉请金额以整数分存储、类别决定加减，支持案件内多组

- **放弃方案**：用浮点数或带正负号的自由数字存储金额，容易产生舍入误差或在“抵扣”类别下出现双负号。
- **决定**：
  - 每案可建多组诉请（`claim_groups`，按 `position` 排序，如“对被告一的诉请”“二审诉请”），每组下挂金额项（`claim_items`）。
  - 金额统一用 `amount_cents BIGINT NOT NULL CHECK (amount_cents >= 0)`（人民币分，或随币种最小单位；首版默认人民币元/分），加减方向由 `category` 决定（`deduction` 抵扣项在合计与瀑布图中减扣，其余类别加总）。
  - 支持从已抽取的 `exact_values(kind='amount')` 选取候选金额并自动带入 `segment_id` 出处，也支持手工录入。

## 后果

- 案件主体表一旦建立，后续的案件事实时间线、资金流向图、证据—待证事实对照表可直接复用 `case_entities` 与 `evidence_catalog`，不必重复建模。
- 审计操作名保持闭集（`audit_events` CHECK 约束），迁移 `0007` 与 `0008` 须同步扩展 `audit.OPERATIONS` 与数据库 CHECK 约束；一致性检查和备份恢复脚本同步纳入新表。
- 关系图与诉请金额各自的迁移拆分为 `0007` 与 `0008`，彼此解耦，可独立实施与验收；首页跨案期限时间轴为只读投影，不触发迁移。
- 单用户、离线、跨案隔离（全表 `(case_id, …)` 组合外键）与结案归档只读守卫继续作为全局不变量适用于所有新表与新命令。
