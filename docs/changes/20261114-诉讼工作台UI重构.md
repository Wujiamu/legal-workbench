## 使用场景与已确认范围

承办人打开本机法律工作台，查看手头诉讼案件的当前节点、期限和下一步工作，进入案件继续整理材料、检索证据或审阅分析。案件内可以自由切换这三个工作区。Agent 可在各工作区按 SOP 完成已有能力支持的任务，并留下便于人工复核的结果。

- 首页为 Dashboard，以案件工作表为主体，提供「新建案件」和进入案件的入口。当前仅做诉讼案件，FTO、无效、专利新申请、OA 答复和补正属于后续候选。
- 案件内显示案件名称。材料目录主要在材料工作区显示。切换工作区后返回时，恢复查询、选中对象或列表位置。宽窗支持命中与来源并排，窄窗可展开来源并返回原位置。结果附近显示索引覆盖和处理不足的提示。
- 从命中打开对应版本的原件 PDF 页或原图，以便核验。材料取得方式、提取文字的方式和标注作者分别有可追溯记录。同一份 PDF 可按页显示文字层提取或 OCR。
- Agent 标注可检索和暂存为工作笔记，并显示待复核。承办人对照原件确认或修订后，记录所复核的标注版本。区分人工标注、Agent 标注及人工修订，转录和内容判断可分别复核。
- 首版以源文件为导入对象。由工作台或本地 Agent 在处理中生成的文本可用于检索和核对，外部预转换 Markdown 的独立导入与页码映射不列入首版。
- 承办人用近期实际诉讼案卷验收，原型准备与开发验证用 `TEST-ONLY` 合成材料。

产品定位见 [PRODUCT.md](../../PRODUCT.md)。

## 方案与数据口径

| 场景 | 首版建议及异常行为 |
|---|---|
| Dashboard | 每案一行，显示名称、当前节点、最近一条未完成的期限及下一步工作。进入案件可看完整事项。近期限优先，逾期及未登记用文字提示。「未登记」与「没有未完成期限」分别显示。 |
| 新建与继续案件 | 发起新建后填写案名，再进入案件概览。当前只有诉讼，创建页可显示固定类型，避免单选项确认。已有案件缺少节点、期限或待办时允许继续办理并补录。 |
| 节点与期限 | 承办人登记办案进度，例如举证准备、庭审准备。案内切换工作区不改变办案节点。每案可登记多条有名称和到期日的期限，区分法院等外部要求与内部计划，案内可查看及标记完成。Dashboard 显示已登记的最近一条未完成期限及其类型。 |
| 来源与定位 | 从当前命中已有的案件、文件版本、位置及提取方式生成可读信息和预览入口。保留 `source_ref`。文件缺失或浏览器无法定位时显示原因及可用的替代动作。能打开文件但无法定位时，显示已知页码及打开本文件入口。 |
| 取得方式 | 保留导入批次来源标签及相对路径。材料详情可单独登记取得方式，检索的来源面板同步显示。未知显示「待补充」。 |
| 标注与复核 | 标注指向同案的具体文件版本及可核验位置。作者、标注内容、人工决定及对应版本可追溯。提交失败保留复核前状态并允许重试。新标注版本重新等待确认。分析成果现有审核状态继续表达该成果自身的审核情况。 |

## 复用与实施顺序

| 阶段 | 范围及可检查结果 | 粗略工作量 | 状态 |
|---|---|---|---|
| 1. 交互原型 | 用合成诉讼案卷演示工作表、新建案件、案内切换、命中对照、原件跳页和标注复核；验证节点与期限读法及宽窗、半屏布局。 | 小，约 1–2 个工作日 | 合成案卷交互已实测 |
| 2. 案件工作表 | 复用案件列表、创建和案内工作区。增补节点、期限和待办的持久化及读写接口，已有案件可正常读取和补录。 | 中，约 2–4 个工作日 | 已实现并验证 |
| 3. 原件核验 | 复用文件预览、解析定位、`read_source` 和 `source_ref`。接通检索到原件的浏览路径，验证 OCR、文字层及图片命中和退出后恢复。 | 中，约 2–4 个工作日 | 已实现并验证 |
| 4. 标注及复核 | 接入同案固定版本的标注、检索和复核。人工录入与 Agent 写入走共享校验。根据确认后的方案更新数据库、HTTP 及所需 CLI/MCP 入口。 | 较大，约 3–5 个工作日，取决于检索和 Agent 写入范围 | 已实现并验证 |
| 5. 验证与试用 | 隔离环境回归，独立复审高风险改动，承办人用真实案件完成试用。 | 按实际变更和试用反馈安排 | 开发验收完成，真实案卷待验 |

估算用于排顺序，尚未包含实际案卷试用与反馈修订。V0.1 案件 API 原先仅有名称、描述等基础字段。本次增加办理信息、单份材料取得方式及标注。页码、提取方式、来源引用和文件完整性检查复用既有实现。受影响的现有入口包括 [案件列表](../../frontend/src/pages/CasesPage.tsx)、[案件工作区](../../frontend/src/pages/CaseWorkspacePage.tsx)、[检索和来源面板](../../frontend/src/components/SearchPanel.tsx)、[案件及来源协议](../../backend/src/legal_workbench/schemas.py) 和 [文件预览](../../backend/src/legal_workbench/api/files.py)。

主要风险是期限缺失或标错、历史引用跳到当前版本、切换命中后旧响应覆盖当前预览，以及人工确认连到错误的标注版本。模型变更先确定旧数据兼容、备份和恢复办法，在隔离数据库验证，再按项目规则安排独立审查。
