# Windows 适配变更单

状态：已封板（部分应用至 v0.1.0 + 2026-11-23 Windows 适配源码；Windows 实机验收已转 NEXT_STEPS）
基线：v0.1.0（0008_claim_amounts，零数据库迁移；承接 2026-11-16 第九轮评估）
最近更新：2026-11-23

## 1. 使用场景与需求确认

- **目标形态**：原生 Windows 10/11（本机安装 Python 3.13、`uv`、Node.js 22+、PostgreSQL 18 + 项目内一键双击桌面启动器）。
- **交付范围**：完整适配（核心跨平台修复 + `scripts/lwb` / `scripts/lwb-launch` + Windows 桌面与命令行启动入口 + 前端快捷键文案按系统自适应 + 跨平台测试 + 文档与 Skill 同步 + Windows 实机自检清单）。
- **OCR 单页超时策略**：POSIX 保留 `SIGALRM`；Windows 采用守护工作线程限时等待（超时即报该页 `failed: timeout` 不阻塞流程；极端 C++ 卡死线程随 worker 进程退出回收）。
- **验证边界**：当前工作机为 macOS，本轮完成全部跨平台改造、Windows 语义模拟单测与 macOS 全量回归，同时提供独立的 Windows 实机验收自检清单；未在真实 Windows 宿主机跑过的端到端项不得标为已通过。

## 2. 盘点发现的真实阻断与差异

| 类别 | 问题位置 | 现有问题 | 适配方案 |
|---|---|---|---|
| **OCR 超时（致命）** | `backend/src/legal_workbench/parsing/ocr.py` | 依赖 Unix 专属 `signal.SIGALRM` / `signal.setitimer`，Windows 触发 OCR 直接 `AttributeError` | 按平台分派：POSIX 主线程保留 `SIGALRM`；无 `SIGALRM` 时改用守护线程 + `threading.Event.wait(timeout)` |
| **PostgreSQL 路径与 locale** | `config.py`、`backup.py`、`cli.py`、`scripts/lwb`、`doctor.py` | `LWB_PG_BIN` 未入 `Settings`；默认硬编码 Homebrew 路径；Windows 强设 `LC_ALL=en_US.UTF-8` 且 `initdb --encoding=UTF8` 在中文 Windows CP936 下报编码冲突 | `config.py` 增加 `pg_bin` 与共享 `resolve_pg_bin()` / `pg_env()`；Windows `initdb` 加 `--locale-provider=builtin --builtin-locale=C.UTF-8`，工具调用加 `.exe` 解析与 UTF-8 子进程解码 |
| **存储与导入路径语义** | `storage.py`、`imports.py`、`app.py` | `safe_name` 未清洗 `<>:"\|?*`、尾部点空格与 `CON`/`NUL`/`COM1..9`/`LPT1..9` 保留名；`managed_path` 依赖 `commonpath` 字符串比较；未拦截 NTFS Junction；`app.py` 静态路径未对齐 `.resolve()` | 清洗 Windows 非法字符与保留名；`managed_path` 增加 `\` 与盘符拦截及 `Path.is_relative_to`；增加 `is_link_or_junction` |
| **CLI / 脚本 UTF-8 输出** | `cli.py`、`mcp_server.py`、`scripts/*` | Windows 默认控制台编码为 CP936/CP1252，输出中文 JSON 或读写配置文件易乱码/报错 | CLI/MCP 启动时重配 `stdout`/`stderr` 为 UTF-8；脚本读写与子进程显式使用 UTF-8 |
| **生命周期与桌面启动** | `scripts/lwb`、`scripts/lwb-launch`、根目录与 `scripts/` | `lwb` 用 `os.execvp`、依赖 `uv run`、无 Windows 启动封装；`lwb-launch` 用 `fcntl`、`/usr/bin/open`、`osascript`、`start_new_session` | `lwb` 优先直调 `.venv` Python、`os.name == "nt"` 改用 `subprocess.run`、支持 `SIGBREAK` 与 `CREATE_NO_WINDOW`；`lwb-launch` 改用跨平台锁（`fcntl` / `msvcrt.LK_NBLCK`）、`os.startfile`、`MessageBoxW`；新增 `法律工作台.bat` 与 `scripts/lwb.cmd` |
| **前端提示文案** | `ProgressPage.tsx`、`CaseProgressPage.tsx`、`ChangeReviewPanel.tsx`、`GraphPrototypePage.tsx`、`SnapshotDrawer.tsx`、`GraphDialogs.tsx`、`localExecutor.ts` | 逻辑已支持 `Ctrl+Z`，但界面全部写死 `⌘Z` | 新增 `frontend/src/ui/shortcuts.ts` 按平台返回 `⌘Z`（Apple）或 `Ctrl+Z`（Windows/Linux） |
| **测试与语料脚本耦合** | `test_backup_consistency.py`、`test_parsing_pdf_ocr.py`、`test_storage.py`、`test_imports.py`、`test_materials.py`、`build_corpus.py`、`generate_dossier.py`、`rehearse_backup_restore.py`、`run_acceptance.py` | 硬编码 Homebrew `PG_BIN`、macOS 字体路径、`/etc/hosts`、`/tmp`、`rm -rf`、无 `target_is_directory` | 统一复用 `resolve_pg_bin()`、跨平台中文字体候选、临时目录/文件替代 `/tmp` 与 `/etc/hosts`、兼容 Windows 1314 符号链接权限并补充 NTFS 语义/保留名/线程超时测试 |

## 3. 业务规则与不变量保持

- 零数据库迁移（维持 `0008_claim_amounts`），不改任何表结构、API 协议、权限模型或服务层业务口径。
- 原件与版本继续走 `staging` → `os.link` 无覆盖发布 → 回读校验，NTFS 同卷硬链接语义保持一致。
- 端口仅绑定 `127.0.0.1`（默认 `8765` 与 `55432`），继续要求本机运行、全离线 OCR 模型校验、无遥测无外部下载。

## 4. 验收条件（AC）

- **AC1**：`config.py` 读取 `.env` / 环境变量 `LWB_PG_BIN` 并能跨平台自动探测 PostgreSQL 18 `bin` 目录；Windows `pg_env()` 不强设 `LC_ALL=en_US.UTF-8`。
- **AC2**：`ocr.py` 在无 `SIGALRM`（含模拟 Windows 分支）时走工作线程限时等待，正常返回 `OcrPage`、超时抛 `TimeoutError`、业务异常原样上抛；POSIX 主线程行为不变。
- **AC3**：`storage.py` `safe_name` 对 Windows 非法字符、尾部点空格与保留设备名安全清洗，不影响既有中文与多点文件名用例；`managed_path` 拦截 `\`、盘符与越界路径（含大小写差异与 junction）。
- **AC4**：`scripts/lwb` 与 `scripts/lwb-launch` 可在单测中模拟 Windows（`os.name="nt"`、`msvcrt`、`CREATE_NO_WINDOW`、`os.startfile`、`MessageBoxW`、`initdb` builtin `C.UTF-8`）及 macOS 原有断库恢复路径全数通过；仓库提供 `法律工作台.bat` 与 `scripts/lwb.cmd`。
- **AC5**：前端撤销提示按平台展示 `⌘Z` / `Ctrl+Z`，macOS / Windows UA 单测均通过，`tsc --noEmit`、`vite build` 与全量 Vitest 通过。
- **AC6**：macOS 本机后端全量 + 新增跨平台测试、前端全量测试、独立代码审查闭环；文档（`README.md`、`docs/ARCHITECTURE.md`、`docs/AGENT.md`、`docs/BACKUP_RESTORE.md`、`docs/TEST_REPORT.md`、`docs/NEXT_STEPS.md`、`CHANGELOG.md`、`.agents/skills/`）及《Windows 实机验收自检清单》全部对齐事实边界。
