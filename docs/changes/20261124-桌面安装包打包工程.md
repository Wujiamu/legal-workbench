# 桌面安装包打包工程（macOS `.dmg` / Windows `.exe`）变更单

状态：已实现待实机验收
基线：v0.1.0 + 0009_case_metadata（承接：20261124-通用Agent插件包.md）
最近更新：2026-11-24

## 1. 目标与范围

把「源码仓库 + 手动命令」的安装方式，推进到「双击安装、开箱即用」的桌面分发形态，同时**不破坏源码态的任何既有行为**（683 个后端测试与全部启动脚本保持兼容）。

四块交付：

1. **只读程序目录与可写数据目录解耦**：新增 `runtime_paths.py`，`config.py` 作为既有调用方的薄门面导出；前端、Alembic、OCR 模型、PostgreSQL 二进制全部按「打包根 → 源码根」解析，数据目录按「`LWB_HOME` → 实例指针 → 平台用户目录（仅打包态）→ 仓库根（源码态）」解析。
2. **桌面统一入口 `desktop_launcher.py`**：冻结后无外部解释器，因此同一可执行文件兼任 server / worker / mcp / cli / doctor 宿主（`--run-*`）；负责首次自动初始化、升级前备份＋迁移、单实例文件锁、优雅退出。
3. **跨平台组装流水线 `packaging/`**：`stage_bundle.py`（载荷组装＋完整性清单）、`plainfolio.spec`（PyInstaller onedir）、`build_macos_dmg.py`（`.app` ＋ `hdiutil`）、`windows/plainfolio.iss`（Inno Setup 6）、`build_windows_exe.py`（串联与编译）。全部支持 `--dry-run`，且**不下载任何外部二进制**。
4. **测试与文档**：`backend/tests/test_packaging_runtime.py`（42 项）、`docs/PACKAGING.md`、本变更单、`docs/NEXT_STEPS.md` 登记。

范围外（本轮明确不做）：真机构建安装包、代码签名与公证、Inno Setup 实机编译、任何 GUI 安装向导验收、向仓库提交 `.dmg` / `.exe` / 便携 PostgreSQL / OCR 模型。

## 2. 关键决定

| 决定 | 理由 |
|---|---|
| 新增 `runtime_paths.py`，`config.py` 只做转发（`ROOT` 仍在 `config` 模块内按调用时读取） | 既完成解耦，又保住 `test_windows_compat.py` / `test_plugin_package.py` 对 `monkeypatch.setattr(config, "ROOT", …)` 的依赖；把 ROOT 挪走会静默废掉这批测试 |
| 源码态 `resolve_home_dir()` 严格回退 `ROOT`，平台数据目录**只在** `is_packaged_mode()` 为真时启用 | 现有用户的数据在仓库根；任何情况下都不能让源码态悄悄改读 `~/Library/Application Support` |
| 打包态子进程用 `[sys.executable, "--run-server"]` 复用自身 | 冻结后没有可用的 `python`；onedir 自调用不会重新解压，启动开销可接受 |
| `console=True` 的单可执行文件，而不是 GUI/CLI 两个 exe | MCP 走 stdio，窗口子系统（Windows GUI）会丢掉 stdout；两个 exe 会让「双击启动」和「MCP 启动」指向不同程序，插件发现逻辑复杂化 |
| 首次初始化的失败路径**删除**半成品（`.env`、`pgpass`、`var/postgres`）并写 `init-failure.log` | `var/postgres` 在而无 `.env` 是「看起来装过但用不了」的最坏状态：`initdb` 会因目录非空失败，启动又会因缺凭据失败。日志只记命令名与退出码，不记命令行（`CREATE ROLE … PASSWORD` 就在命令行里） |
| 升级前备份用 `backup.py` 的完整流程并 `verify_backup()` 全量复核，失败即中止 | 「有 dump 文件」不等于「有可用备份」；迁移不可逆，宁可不启动 |
| 安装包只装程序，用户数据目录由程序自己创建；卸载段只删 `{app}\*.log` | `%LOCALAPPDATA%\PlainFolio` 里是案件库与备份，误删不可恢复。静态检查 + 反向验证双重守护 |
| `--dry-run` 默认不要求便携 PG18 / OCR 模型 | 这两样按红线不入库，干跑必须在干净开发机上可用；严格校验留给真实构建 |
| 实例指针增加可选 `mode` / `executable`，只在冻结态写入 | 插件启动器据此改派 `<exe> --run-mcp`；源码态写 `sys.executable` 会把解释器当桌面程序，属于错误信息 |
| 插件启动器对「声称 packaged 但 executable 不存在」的指针直接拒绝，不退回按文件名探测 | 安装目录被移动时，猜一个同目录的程序去启动，比明确失败更危险 |
| `stage_bundle` 要求便携 PG 的**整个根目录**（含 `share/`） | `initdb` 依赖 `share/` 下的建库脚本，只拷 `bin/` 会得到「能启动、不能建库」的包 |

## 4. 验收条件与结果

| 验收条件 | 结果 |
|---|---|
| `is_packaged_mode()` 识别 `LWB_PACKAGED` 的 `1/true/yes/on` 与 `sys.frozen`，其余为假 | 通过（含大小写与空格） |
| `resolve_bundle_root()` 优先级：`LWB_BUNDLE_ROOT` → 冻结资源根（`_MEIPASS`／可执行文件同级）→ `ROOT` | 通过 |
| `default_user_data_dir()`：macOS `~/Library/Application Support/PlainFolio`、Windows `%LOCALAPPDATA%\PlainFolio`（缺该变量回退 `~/AppData/Local`）、Linux `~/.local/share/plainfolio` | 通过 |
| 源码态 `resolve_home_dir()` 回退被 monkeypatch 的 `ROOT`；打包态回退平台数据目录；`LWB_HOME` / 指针始终优先 | 通过（3 个用例） |
| `resolve_frontend_dist()` / `resolve_alembic_ini()` / `resolve_migrations_dir()`：显式覆盖 → 打包根 → 源码根 | 通过 |
| `load_settings()`：显式 `LWB_OCR_MODEL_DIR` 优先，否则内嵌非空模型目录，否则 `home/var/models` | 通过 |
| `resolve_pg_bin()`：显式参数 → `LWB_PG_BIN` → 内嵌 `runtime/postgres/bin` → `PATH` → 系统默认路径 | 通过（原有 Windows 探测用例同时保持通过） |
| 冻结态子进程命令为 `--run-server` / `--run-worker` / `--run-mcp` / `--run-doctor` / `--run-cli …` / `--start-db`；源码态仍为 `-m` 模块形式 | 通过 |
| 首次初始化：`initdb`（Windows 带 `--locale-provider=builtin --builtin-locale=C.UTF-8`）→ 集群配置 → `pgpass` → 两角色＋库 → `.env`（0600，两角色口令互不相同且 ≥32 字节）→ 迁移 → 实例指针（无任何凭据） | 通过 |
| 初始化失败：停止临时集群、删除 `.env`／`pgpass`／`var/postgres`、写不含口令的 `init-failure.log`、不写指针、状态回到 `fresh` | 通过（两个失败点：建库失败、迁移失败） |
| 升级：revision 一致时既不备份也不迁移；有待执行迁移时先备份再迁移；备份失败时迁移与启动都不发生 | 通过（3 个用例） |
| 打包态 MCP：指针含 `mode`/`executable` 时启动器派发 `<exe> --run-mcp`，不设 `PYTHONPATH`；`--print-plan` 显示 `packaged`；`LWB_MCP_AUTO_START_DB=1` 时派发 `<exe> --start-db` | 通过 |
| `stage_bundle.py` 正常校验并写出 `bundle-manifest.json`（含各组件 SHA-256 与迁移 head）；缺 PG 二进制或迁移链分叉时拒绝；`--allow-missing-runtime` 才放行 | 通过（5 个用例） |
| `build_macos_dmg.py --dry-run` 与 `build_windows_exe.py --dry-run` 在当前 macOS 上退出码 0，输出确定的构建计划 JSON | 通过 |

## 7. 风险与未验证项

1. **未真实构建**：本机未安装 PyInstaller，未产出 `.dmg` / `.exe`；`plainfolio.spec` 的 `collect_data_files` 清单（`rapidocr_onnxruntime` / `onnxruntime` / `pypdfium2`）需要在真机构建时核对，可能还需补 `binaries` 或 `hiddenimports`。
2. **便携 PostgreSQL 18 未随仓库提供**：其可重定位性（尤其 macOS 的 `@rpath`）必须在真机验证，否则安装包在目标机器上无法 `initdb`。
3. **`.iss` 未在 Inno Setup 中编译**：模板结构、语言文件与卸载安全规则由静态检查和反向用例守护，但真实编译依赖构建机的 `ChineseSimplified.isl`（官方安装包不自带）。
4. **未签名、未公证**：Gatekeeper / SmartScreen 的实际提示未记录。
5. **打包态 MCP 只做过桩验证**：未在真实 Codex / DSH 客户端中通过 `<exe> --run-mcp` 跑通会话。
6. **安装包体积未实测**：onedir ＋ PG18 ＋ ONNX 预计 300–500 MB。
7. **未实机验收**：首次自动建库、单实例、退出停库、升级前备份、卸载不删数据等 8 类行为只在单元测试层面验证，真机清单见 [PACKAGING.md](../PACKAGING.md) 第 8 节。
8. **L1 契约未全部同步**：`docs/TEST_REPORT.md`、`docs/AGENT.md` 与本单相关的补充留到实机验收封板时一并刷新；`README.md` / `ARCHITECTURE.md` 已补打包形态说明并标注「未实机验收」。
