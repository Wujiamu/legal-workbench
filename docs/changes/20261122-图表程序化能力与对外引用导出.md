## 一、目标与核心范围

本期聚焦**零数据库迁移、确定性最高、直接复用 `0008_claim_amounts` 现有底座**的程序化能力，彻底把关系图等可视化成果从“纯手动/AI 黑盒”升级为“**程序铺路、防漏可审计、内部极简、对外强引用**”：

1. **全图表通用的“一源三态导出 + 程序硬门禁 + 复核审计包”底座**（首期接入**主体关系图**与已有**诉请金额瀑布图 `WaterfallChart`**，为后续所有新图定型接口）。
2. **主体关系图程序化助手**：画布双主体全案共现秒查（展开全部别名＋同段金额/日期）、阅卷 `SourcePreview` / 标注选中片段一键送入关系图。
3. **全案只读“防漏与暗线审计面板” ＋ 案卷健康度与引用覆盖格子图**：材料覆盖缺口、高确定性孤儿机构差集、基于现有 `exact_values` 的强指纹跨文档碰撞（手机号、统一社会信用代码、银行账号、电子邮箱）。
4. **主体冷启动与结构化表格确定性出边**：程序化提取文书首部当事人与合同简称定义进入“候选主体与别名消歧台”；通用 XLSX/CSV 列映射确定性汇总生成资金/股权关系草稿（不硬编码具体银行或企查查格式）。
5. **外部复核 Skill 规范与配套模板**：消费工作台 `export-chart-audit-bundle` 审计包，承担文图逐字一致性、证明力越界与口径自认风险的实质核查。

### 本期明确不做（严禁开工 Agent 越界扩scope）

- 不新增数据库表或 Alembic 迁移（保持 `0008_claim_amounts` 兼容与现有备份恢复零冲击）。
- 不在工作台内置 LLM 或任意代码执行沙箱；复核 Skill 与非标脚本解析规程均运行在外部 Agent 侧。
- 不硬编码特定银行流水、企查查/天眼查或电子发票格式。
- 不引入正则盲扫中文自然人姓名（高误报）；不碰复杂法律要件规则推理机；不做任何已列入 [D4 淘汰清单](../decisions/20261122-图表程序化与对外引用契约.md#d4横向反过度可视化红线与明确淘汰边界) 的功能。
- 多轨事实时间线、争点树、证据覆盖矩阵、GIS 多图层等需要新表或二期设计的能力留待 [二三期路线单](20261122-横向可视化与二三期图表演进路线.md) 另行立项。

### Wave 1 · 通用一源三态导出底座 ＋ 共现秒查 ＋ 只读防漏与暗线审计（核心交付，约 4–5 天）

Wave 1 全部为**只读分析与导出能力＋既有写命令调用**，不改表结构、风险最低、价值最直接。内部可拆为 **3 个低耦合子包（1A / 1B / 1C）支持多 Agent 并行**。

#### 子包 1A：跨图表“一源三态”导出、硬门禁预检与复核审计包

- **后端新建** `backend/src/legal_workbench/chart_export.py`（纯共享服务，先支持 `chart_type="graph"` 与 `chart_type="claims"`，预留统一适配器注册表供未来新图接入）：
  1. **统一导出配置（`profile`）**：
     - `working`（内部工作态）：保留全部展示状态；画布默认简洁，可开关编号角标；
     - `client`（客户沟通态）：自动剔除 `pending` Agent 提案、`ruled_out` 已排除关系与全部内部 `note`；对纳入元素按序分配紧凑引用角标 `[1]..[N]` 并生成精简底注/脚注表；输出快照版本（若有）、导出日期与“含待查项”提示水印；
     - `court`（当庭呈递态）：强制剔除 `pending`、`ruled_out` 与内部 `note`；强制绑定不可变快照（对 `graph` 要求指定或先冻结 `snapshot_id`；对 `claims` 输出当前不可变导出摘要与时间戳）；实时调用 `evidence_catalog.resolve_labels()` 解析最新正式编号，生成规范角标与配套 **《图示引用索引附表》**（支持 Markdown 与 CSV 两种导出格式：角标序号｜图中对象/断言｜证据编号｜证据名称｜精确页码/定位｜证明要点｜原件文件名与版本）。
  2. **确定性硬门禁预检 `preflight_chart_export(...)`**：
     - 返回结构化检查项列表（每项带 `severity: 'blocker' | 'warning'`、`code`、`target_id`、`message`）：
       - `pending_changes_present`（存在未确认 Agent 变更：`court` 为 `blocker`，`client` 为 `warning`）；
       - `missing_source`（纳入展示的关系/诉请项无任何出处：`court` 为 `blocker`）；
       - `uncataloged_source`（所引材料尚未编入已确认证据目录，显示“未编号”：`court` 为 `blocker`，`client` 为 `warning`）；
       - `suspected_in_court`（`suspected` 待查关系纳入当庭范围：`court` 为 `blocker`，需从当庭导出勾选排除或显式确认转为“待举证主张”标注）；
       - `source_integrity_warning`（所引片段/材料已软删、解析为 `failed`/`partial`/`pending`，或快照冻结编号相对现行目录已发生漂移：`court` 软删为 `blocker`，解析告警/编号漂移为 `warning`）。
     - 明确规则：当庭版存在 `blocker` 时默认拒绝导出；仅允许人工入口在前端显式勾选项级豁免并生成豁免说明记录（Agent 入口不可跳过）。
  3. **只读复核审计包 `build_chart_audit_bundle(...)`**：
     - 面向外部复核 Skill 的标准 JSON 输出：包含 `chart_meta`（案件 ID、图类型、标题、快照/版本、导出模式）、`assertions[]`（每条对外展示的节点/关系/诉请项的完整展示文案、数值/日期、可信状态、绑定的全部正式证据编号，以及**由 `search.read_source` 实时拼装的对应 `segment_id` 原文上下文与页码**）、`preflight`（完整硬门禁结果）。
     - 严守不变量：绝不跨案读取，绝不泄漏数据库凭据，绝不包含归档或已软删且未纳入展示的内部备注。
- **入口扩展**：
  - HTTP（新建 `backend/src/legal_workbench/api/chart_export.py` 并在 `app.py` 挂载）：
    - `POST /api/v1/cases/{case_id}/charts/preflight`
    - `POST /api/v1/cases/{case_id}/charts/citation-table`（返回 JSON / Markdown / CSV 索引附表）
    - `GET /api/v1/cases/{case_id}/charts/audit-bundle`（只读审计包）
  - CLI（`cli.py`）与 MCP（`mcp_server.py`）：
    - 新增只读命令/工具 `export-chart-audit-bundle`（必须显式传 `--case-id`、`--chart-type graph|claims`、`--target-id`、`--profile client|court`，可选 `--snapshot-id`）。
- **前端扩展**：
  - `frontend/src/graph/exportSvg.ts`：重构支持 `profile: 'working' | 'client' | 'court'` 渲染开关——默认工作态保持画面简洁（不堆编号），客户态/当庭态在边/节点上渲染紧凑数字角标 `[1]` 与底部图例/版本/日期/水印，并可同步下载配套《图示引用索引附表》（`.md` / `.csv`）；
  - `frontend/src/graph/GraphWorkspace.tsx` & `SnapshotDrawer.tsx`：升级原“导出”按钮为“三态导出对话框”（选模式 → 实时展示硬门禁清单与红/黄定位跳转 → 当庭态引导选择或一键冻结快照 → 下载 SVG/PNG + 索引附表）；
  - `frontend/src/claims/WaterfallChart.tsx` & `ClaimsPanel.tsx`：新增同款三态导出与《诉请引用索引附表》下载（直接复用新建通用导出组件 `frontend/src/components/ChartExportDialog.tsx`）。

#### 子包 1B：主体关系图程序化助手（双主体共现秒查 ＋ 阅卷一键入图）

- **后端新建** `backend/src/legal_workbench/graph_assist.py`（只读分析服务）：
  - `find_entity_cooccurrences(session, case_id, entity_a_id, entity_b_id, scope="originals", limit=50)`：
    - 读取 A、B 两个未软删主体的主名与全部未软删 `entity_aliases`（自动过滤过短单字/通用停用词，并把实际使用的检索词列表回传给前端透明展示）；
    - 复用 `search._active_runs` 在同案活跃 `segments` 中做确定性共现匹配（**同段命中优先，同页/同 sheet 次之**）；
    - 顺带关联同 `segment_id` 下已抽取的 `exact_values`（`amount` 与 `date`），返回片段文本、`SourceLocation`、页码、已解析证据编号以及 `match_terms`。
  - `match_entities_in_segment(session, case_id, segment_id)`（或按 `material_id + page`）：
    - 确定性扫描该片段文本，匹配当前案件已有主体（主名＋别名）与同段 `exact_values`（金额/日期），供阅卷一键入图时自动预填表单。
- **HTTP 入口**（挂在 `api/graph.py`）：

  - `frontend/src/components/SourcePreview.tsx` & `SearchPanel.tsx` & `Annotations.tsx`：

#### 子包 1C：只读“防漏与暗线审计面板” ＋ 案卷健康度与引用覆盖格子图

- **后端扩展 `graph_assist.py`**（纯只读查询，零写入）：
  1. **案卷覆盖健康度与引用矩阵 `get_corpus_coverage_matrix(session, case_id, graph_id=None)`**：
     - 复用 `coverage.py`（`coverage_for_version`）＋ 统计每份材料是否被 `graph_sources` / `evidence_item_bindings` / `annotations` / `claim_items` 引用；
     - 按材料 `category` × 状态（`referenced` 已入图或已引用 / `parsed_unused` 已解析未引用 / `partial_or_failed` OCR 告警或解析失败 / `pending_or_unsupported` 未解析或不支持）输出聚合格子统计与明细列表，点击格子直达对应材料列表。
  2. **高确定性孤儿机构差集 `find_orphan_orgs(session, case_id, min_mentions=2)`**：
     - 仅在同案活跃 `segments` 上用严格机构正则（覆盖 `有限责任公司`、`有限公司`、`股份有限公司`、`合伙企业`、`银行.*(?:支行|分行)`、`人民法院`、`仲裁委员会`、`事务所` 等强尾缀）以及文书首部当事人行（`原告/被告/第三人/申请人/被申请人：`）抽取机构名，做全角/空格归一化与去重计数；
     - 与全案有效 `case_entities.name` 及 `entity_aliases.alias` 做归一化差集，返回出现频次 ≥ `min_mentions` 的未入图机构、涉及材料数与样例 `segment_id`（**严禁使用正则猜测中文自然人姓名**）。
  3. **基于 `ExactValue` 的强指纹跨文档碰撞 `find_identifier_bridges(session, case_id)`**：
     - 读取同案活跃 `exact_values(kind='identifier')` 并辅以文本邮箱正则，做严格强指纹收窄过滤，仅保留 4 类高置信标识符：
       - `cn_mobile`：11 位中国大陆手机号（`1[3-9]\d{9}`，前后非数字）；
       - `uscc`：18 位统一社会信用代码（标准字符集校验，校验位通过优先）；
       - `bank_account`：15–19 位纯数字且周边 30 字符内含银行/账号/卡号/开户行/户名等上下文关键词（避免把长编号/保单号误报成银行卡）；
       - `email`：标准电子邮箱地址。
     - 按标准化后的 `(fingerprint_kind, fingerprint_value)` 聚合，只保留**跨 ≥2 份不同材料**或**周边上下文分别命中 ≥2 个不同已录入主体**的碰撞组；返回双方 `segment_id`、`material_id`、周边摘录与命中主体提示。
- **HTTP 入口**（挂在 `api/graph.py` 与 `api/materials.py`）：
  - `GET /api/v1/cases/{case_id}/graphs/assist/audit?graph_id=...`
  - `GET /api/v1/cases/{case_id}/materials/coverage-matrix`
- **前端扩展**：
  - 关系图页工具栏新增只读抽屉**“防漏与暗线审计”**（三页签：覆盖缺口 / 孤儿机构 / 强指纹碰撞）：
    - 孤儿机构支持点原文核对或一键“添加为案件主体”（走 `add_entity`）；
    - 强指纹碰撞支持左右并排查看两端原文，确认后一键打开新建 `affiliate` 关系对话框并预挂两边 `segment_id` 出处。
  - 材料工作区（或案件概览）上方新增可折叠的**“案卷健康与引用覆盖格子图”**（纯语义化 HTML 表格/CSS Grid 色块矩阵，零新增图表库，点击任意色块直接筛出对应材料）。

### Wave 2 · 主体冷启动消歧 ＋ 通用表格列映射确定性出边（约 3–4 天）

#### 子包 2A：程序化“候选主体 & 别名词典”初筛 ＋ 消歧合并台

- **后端扩展 `graph_assist.py`**：
  - `extract_entity_alias_candidates(session, case_id, material_ids=None)`（纯只读）：
    1. **文书首部当事人解析**：解析起诉状、答辩状、裁定书/判决书、仲裁申请书首部的 `原告/被告/第三人/法定代表人/委托诉讼代理人` 固定句式，抽全称、推定主体类型（法人/自然人）与诉讼角色建议；
    2. **合同简称定义解析**：匹配 `甲方|乙方|丙方|丁方|卖方|买方|出借人|借款人|保证人|发包人|承包人` 后的全称及 `（以下简称[“"「]?([^”"」)]{2,20})[”"」]?）` 定义，生成 `(主体全称, 候选简称/角色别名)` 对；
    3. **机构全称频次汇总**：复用 1C 机构提取并按相似前缀/包含关系自动归簇（如 `北京XX科技有限公司` 与 `XX科技公司` 标为“疑似别名待合并”）。

## 四、关键业务规则与不变量（开工 Agent 必守）

1. **零数据库破坏**：本期不改既有 `0001–0008` 表结构与历史 `source_ref` 不可变性；所有写操作统一走现有 `graph.py` 服务命令（保留 `begin_write`、归档守卫、CAS、审计、`case_change_seq`）。
2. **跨案隔离**：所有只读分析（共现、孤儿、强指纹、覆盖矩阵、导出预检、审计包）必须严格限定 `case_id`，跨案传入实体/材料/快照 ID 一律返回 `case_mismatch`（400/404 沿用现行错误协议）。
3. **对外导出防泄漏铁律**：`client` 与 `court` 模式下，**绝对禁止**将 `pending` 提案、内部 `note`、`ruled_out` 边泄漏到导出 SVG/PNG 或《图示引用索引附表》中；须有专门负向单测验证。
4. **当庭版强制门禁与编号唯一性**：编号全部来自 `evidence_catalog.resolve_labels()`，不自造第二套编号逻辑；当庭版遇 `blocker` 时默认拒绝输出，且 `court` 导出必须绑定快照（或记录明确冻结时间戳）。
5. **强指纹与孤儿提取宁缺毋滥**：宁可漏报少数不规范简称，绝不把页码/日期/普通订单号误报为银行卡号，绝不用正则乱切中文自然人姓名造成海量垃圾。
6. **表格金额精度**：Wave 2B 表格聚合一律使用 `Decimal` 精确计算后再转整数分，禁止浮点累加；空行或异常金额行明确进入 `skipped_rows` 报告，绝不静默丢弃或当作 0。
7. **前端交互底线**：沿用原生 `<dialog>`、语义化表单与 CSS 自定义属性；中文输入法组词回车不得误触发提交；支持 macOS Chromium 与 Safari 及 760px 半屏布局。
