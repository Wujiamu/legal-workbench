## 一、已确认的需求与口径（2026-11-20）

### 第一轮确认（方向与核心机制）

1. 做诉讼案件的**主体关系图**：至少包括主体和主体之间的关系；关系不清楚时用醒目颜色的虚线表示。
2. **关系可信程度分四档**：

   | 状态（值） | 线型与颜色 | 含义 |
   |---|---|---|
   | 有证据（`evidenced`） | 实线 | 至少关联一条有效出处 |
   | 待查 / 存疑（`suspected`） | **红色粗虚线** | 怀疑存在，尚无证据 |
   | 对方主张 / 有争议（`disputed`） | 橙色点线 | 对方主张，我方不认可 |
   | 已排除（`ruled_out`） | 灰色 + 删除标记 | 查证不成立，保留备查 |

3. **图给承办人自己看**：不追求正式出庭排版模板，但**引用和证据不能少**。
4. **证据编号随目录更新**：证据编号确定、证据目录编写完成后，图中显示的证据编号随之自动更新。
5. **双主体来源、双向可编辑**：主体既可人工录入，也可由 Agent 从材料识别；图由人工与 Agent 两边均可编辑（Agent 变更进入待确认）。
6. **版本快照**：可将某一版固定为不可变快照，记录不同沟通阶段、庭审阶段的版本并支持对比。
7. **客户同意标签**：挂在快照上，记录客户同意时间与同意来源。
8. **并行推进**：与[期限时间轴与诉请金额](20261120-期限时间轴与诉请金额.md)均纳入计划，不互相阻塞。

### 第二轮确认（细节答复）

| 问题 | 用户答复 | 落实方式 |
|---|---|---|
| Q1 证据目录编写位置 | 工作台内维护与外部导入**两者都要** | 工作台内证据目录为唯一编号来源；支持导入外部 Word / Excel 目录，Agent 解析并生成材料对应建议，经人工确认后生效 |
| Q2 证据编号格式 | **`证据1-1`** 这种写法 | 目录分“证据组 → 组内条目”，按序自动生成 `证据{组}-{序}`；命中具体页码/片段时追加页码（如 `证据1-1 第5页`） |
| Q5 客户同意范围 | 留一个**备注栏**，输入提示写“例如：客户部分同意” | 同意记录增加可选 `note` 字段，前端 `placeholder="例如：客户部分同意"` |
| Q6 图的数量 | **一案多图** | 主体、别名、关系、出处属于案件（全案唯一维护）；每张图是命名视图，各自保存纳入的节点/边、布局坐标与分组；快照按单张图冻结 |
| Q3、Q4 | 未单独修改，按默认口径进入原型 | Q3：快照保留冻结时的编号，若现行目录已变则旁注“现为证据 X-Y”；Q4：阶段标签预置“初次沟通 / 方案沟通 / 起诉前 / 庭前 / 庭后 / 二审”＋自定义，可关联一个进度节点。看原型时确认 |

## 二、使用场景

- **接案梳理**：先画出当事人、关联公司和关键自然人，尚未查明的关系画成红色粗虚线列为待查。
- **按专题分图**：同一案件建多张图（如“股权与实控结构”“资金与担保链条”），共享同一批主体和关系，互不重复录入。
- **阅卷补证**：查阅工商档案、合同、流水后，给关系挂上 `source_ref` / 材料 / 标注，将红色虚线改为实线或标为已排除。
- **Agent 协同**：Agent 读完案卷后经 MCP 提交候选主体、别名、关系和出处，网页弹出黄色“Agent · 待确认”徽标，承办人逐条确认、一键确认或撤回。
- **目录联动**：在工作台维护或导入外部证据目录并确认绑定后，全图出处自动显示为 `证据1-1 第5页`；目录插删重排后工作稿编号立即更新。
- **阶段定稿与客户确认**：方案沟通、起诉前、庭前、庭后分别冻结快照；客户通过微信/邮件/会议确认某版后，在该快照上登记同意时间、来源、凭证材料与备注，并可随时对比前后两版变化。

## 三、目标与范围

### 首版范围

| 能力 | 说明 |
|---|---|
| 主体（案件级） | 类型（自然人 / 法人或组织 / 机关 / 法院 / 其他）、名称、多个别名、多个诉讼角色（原告 / 被告 / 第三人 / 证人 / 案外人等）、备注、出处 |
| 关系（案件级） | 起点、终点、有向或无向、类型（规则配置驱动）、四档可信状态、属性（持股比例 / 金额 / 起止日期）、备注、出处 |
| 出处关联 | 主体与关系均可挂多条出处：`segment_id`（即 `source_ref`）、`material_id` 或 `annotation_id` 三选一，每条可附一句“证明要点”，点击直达 `SourcePreview` 原文/原页 |
| 证据目录与编号 | 组 + 条目结构，自动按序生成 `证据{组}-{序}`；每条支持绑定一份或多份材料（全部或页码范围）；支持工作台内编辑、导出表格，以及导入外部 Word/Excel 目录后由 Agent 建议绑定并待人工确认 |
| 一案多图 | 案件内可新建、重命名、删除多张关系图；从案件主体/关系池挑选加入本图；拖拽节点并持久化每张图各自的 `(x, y)` 坐标；分组框可收起/展开 |
| 协同编辑与撤销 | 人工修改直接生效；Agent 修改进入待确认（沿用进度页黄色/绿色 `Agent` 徽标、逐条确认/一键全部确认/撤回、分区撤销与 `⌘Z`） |
| 版本快照与对比 | 按图冻结不可变快照（含冻结时编号），记录阶段标签、说明与可选进度节点；支持“两份快照对比”及“快照 vs 当前工作稿”差异高亮；支持“恢复为工作稿”（记入变更记录、可撤销） |
| 客户同意 | 仅挂在快照上：同意人、客户实际同意时间（可补录）、同意方式、来源说明、可选凭证材料、备注（占位提示“例如：客户部分同意”）、系统登记时间；不可修改，撤回/更正以追加记录保留 |
| 筛选、路径高亮与导出 | 按可信状态 / 关系类型筛选；选中两个主体高亮二者间所有连通路径；导出带图例的 PNG / SVG 供自留打印 |

### 首版不做

- 接入企查查等外部数据源（工作台离线运行，外部工商信息由 Agent 查询后经待确认写入）。
- 时间轴滑块动态回放关系演变（首版先存关系的 `date_start` / `date_end`，交互放到后续增量）。
- 正式出庭专用排版模板（图定位为承办人自用，带图例与证据编号即可）。
- 多用户协作与权限分级。

## 四、业务规则与不变量

1. **类型由规则配置驱动**：主体类型、诉讼角色预设、关系类型、可信状态、快照阶段预设、同意方式与 Agent 命令白名单集中定义在 `graph_rules.py` 并通过只读接口提供给前端（新增类型不改表结构）。首版关系类型：`equity_control`（股权/控制）、`office_rep`（任职/代表）、`contract`（合同相对方）、`guarantee`（担保）、`debt`（债权债务）、`fund_flow`（资金往来）、`agency`（代理）、`kinship`（亲属）、`affiliate`（关联）、`other`（其他）。
2. **证据编号唯一来源（[D2](../decisions/20261120-主体关系图与证据目录模型.md)）**：图不存编号文本，只存稳定引用。展示时将引用解析到 `(material_id, page)`，匹配已确认的目录绑定输出 `证据{组}-{序}`（多页追加 `第N页`；命中多个目录条目按序全部列出；未命中显示材料名＋“未编号”）。
3. **“有证据”必须有出处**：服务层与前端同时约束——无出处的关系不可设为 `evidenced`；删除 `evidenced` 关系的最后一条出处时，命令必须同时提供新状态（`suspected` / `disputed` / `ruled_out`），否则拒绝，系统不静默降级。
4. **一案多图语义（[D1](../decisions/20261120-主体关系图与证据目录模型.md)）**：
   - 主体、别名、关系、出处全案共享，在 A 图修改状态或出处后 B 图即时同步。
   - 在某图新建主体或关系时，写入案件池并自动加入当前图；若在某图加入已有关系，两端主体若不在本图则自动纳入本图。
   - “从本图移除”仅删除图内成员记录；“删除主体/关系”为案件级软删除，删除前返回并展示受影响的图清单及数量。
5. **快照不可变与待确认隔离（[D3](../decisions/20261120-主体关系图与证据目录模型.md)）**：
   - 冻结快照时，若涉及本图的主体、关系、出处或目录绑定存在 `pending` 状态 Agent 变更，冻结前返回待确认数量提示；继续冻结则仅按已确认状态生成快照，不包含待确认变更。
   - 快照只读不可编辑；“恢复为工作稿”以反向/覆盖命令作用于当前工作稿，记录到 `graph_changes` 并支持撤销。
6. **客户同意追加留痕（[D3](../decisions/20261120-主体关系图与证据目录模型.md)）**：同意记录只能挂在快照上，写入后不可修改或删除；撤回或更正通过追加一条 `action='revoke'` 或 `action='amend'`（指向原 `parent_consent_id`）实现。
7. **权限与幂等**：`actor` 由入口固定（HTTP=`human`/`local-web`，MCP=`agent`/`mcp`，CLI=`agent`/`cli`），调用方不可自报。快照冻结/恢复、客户同意、确认/撤回 Agent 变更仅限人工入口。Agent 新建主体/关系/目录条目须带 `request_key` 保证幂等；同名或疑似别名主体不自动合并，记为提示供人工处理。
8. **归档只读与案件隔离**：案件 `archived_at` 非空时，关系图、证据目录、快照、同意的全部写命令被拒，查看与导出正常。全部新表带 `case_id` 及 `(case_id, …)` 组合外键，跨案引用由 PostgreSQL 拒绝，服务层返回 `case_mismatch`。

## 五、详细技术设计

### 5.1 数据库：迁移 `0007_graph_evidence`

全部表遵循现有约定：UUID 主键、`UNIQUE(case_id, id)` 支撑组合外键、`revision` 乐观锁 CAS、软删除 `removed_at`、不改旧表列（仅扩展 `audit_events` 操作名 CHECK 约束）。

#### A. 案件主体与关系（案件级）

```sql
case_entities(
  id uuid PK, case_id uuid NOT NULL → cases,
  kind text NOT NULL,                       -- 规则配置校验：person/org/agency/court/other
  name text NOT NULL (≤200),
  roles jsonb NOT NULL DEFAULT '[]',        -- 诉讼角色标签数组，如 ["被告","担保人"]
  note text NULL (≤4000),
  created_by text CHECK IN ('human','agent'),
  updated_by text CHECK IN ('human','agent'),
  request_key text NULL, UNIQUE(case_id, request_key),
  removed_at timestamptz NULL, revision int NOT NULL DEFAULT 0,
  created_at, updated_at, UNIQUE(case_id, id))

entity_aliases(
  id uuid PK, case_id uuid NOT NULL,
  entity_id uuid NOT NULL → (case_id, case_entities.id),
  alias text NOT NULL (≤200),
  created_by text CHECK IN ('human','agent'),
  removed_at timestamptz NULL, created_at,
  UNIQUE(case_id, id))                      -- 部分唯一索引：(case_id, entity_id, lower(alias)) WHERE removed_at IS NULL

case_relations(
  id uuid PK, case_id uuid NOT NULL → cases,
  from_entity_id uuid NOT NULL → (case_id, case_entities.id),
  to_entity_id uuid NOT NULL → (case_id, case_entities.id),
  directed boolean NOT NULL DEFAULT true,
  kind text NOT NULL,                       -- 规则配置校验
  label text NULL (≤200),                   -- 边上自定义短标签，如"持股60%"
  credibility text NOT NULL CHECK IN ('evidenced','suspected','disputed','ruled_out'),
  attrs jsonb NOT NULL DEFAULT '{}',        -- {share_pct, amount_cents, currency, date_start, date_end}
  note text NULL (≤4000),
  created_by text CHECK IN ('human','agent'),
  updated_by text CHECK IN ('human','agent'),
  request_key text NULL, UNIQUE(case_id, request_key),
  removed_at timestamptz NULL, revision int NOT NULL DEFAULT 0,
  created_at, updated_at,
  CHECK (from_entity_id <> to_entity_id), UNIQUE(case_id, id))

graph_sources(
  id uuid PK, case_id uuid NOT NULL → cases,
  entity_id uuid NULL → (case_id, case_entities.id),
  relation_id uuid NULL → (case_id, case_relations.id),
  segment_id uuid NULL → (case_id, segments.id),         -- 不可变 source_ref
  material_id uuid NULL → (case_id, materials.id),
  annotation_id uuid NULL → (case_id, annotations.id),
  proves text NULL (≤500),                               -- 一句话说明"证明要点"
  created_by text CHECK IN ('human','agent'),
  removed_at timestamptz NULL, created_at,
  CHECK (num_nonnulls(entity_id, relation_id) = 1),
  CHECK (num_nonnulls(segment_id, material_id, annotation_id) = 1),
  UNIQUE(case_id, id))
```

> 证据目录编号解析规则：仅 `removed_at IS NULL` 且 `review_state = 'confirmed'` 的分组、条目与绑定参与计算；组号 = 有效分组按 `(position, id)` 的 1-based 序号，条号 = 组内有效条目按 `(position, id)` 的 1-based 序号，格式化为 `证据{组}-{序}`。若引用含页码且条目仅覆盖部分页或精确片段，追加 `第{page}页`。
