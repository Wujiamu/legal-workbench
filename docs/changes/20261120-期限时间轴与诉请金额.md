## 一、首页跨案期限时间轴

### 1.1 场景与问题

首页案件工作表（`CasesPage`）目前只展示每个案件最近一条未完成期限。承办人需要一眼看清未来几周全部在办案件的期限分布、逾期项和密集日期（扎堆提醒）。

### 1.2 范围、数据与业务规则

- **只读投影，不新增表、不迁移数据库**：数据直接来自 `cases.deadlines` JSONB（`title`、`due`、`kind: external|internal`、`completed`），过滤 `archived_at IS NULL` 的在办案件。
- **避免分页截断**：现有 `GET /api/v1/dashboard` 按 50 条分页；当在办案件超过 50 个时，仅从当前页拼装时间轴会漏掉后页期限。因此新增一个轻量只读接口 `GET /api/v1/dashboard/deadlines`（读取全部未归档案件的期限并按日期排序，不修改表结构）。
- **时间窗口与时区（Q1 已确认默认口径）**：
  - “今天”按 `Asia/Shanghai` 计算（复用 `frontend/src/ui/time.ts` 统一日期口径，消除客户端系统时区偏差）。
  - 默认窗口：**今天前 7 天至今天后 60 天**；支持快速切换窗口：`前7天~后30天`、`前7天~后60天（默认）`、`前7天~后90天`、`全部未完成`。
  - **超期兜底**：早于窗口左边界（例如已逾期 15 天）但仍未完成的期限，不能静默隐藏，固定汇总在时间轴最左侧“更早逾期（N）”红色区域。
- **视觉与交互**：
  - 位置：首页案件工作表上方可折叠/常驻面板（不挤占表格主体）。
  - 区分样式：外部期限（`external`，深绿/边框强调）与内部计划（`internal`，浅灰虚线边框）；逾期未完成标红（沿用 `.overdue` `#9c302a`）；已完成期限默认隐藏，提供“显示已完成”复选框。
  - 同一天有多条期限时纵向堆叠显示，并标出案件简称与期限事项。
  - 点击任意期限卡片直接跳转到 `/cases/{case_id}?view=overview`。
  - 响应式：宽屏为横向日期轨道（含“今天”竖线锚点）；760px 及以下半屏自动切换为按日期分组的紧凑纵向列表，保证无横向溢出卡顿。
  - 实现方式：纯语义化 HTML + CSS（不新增图表库）。

### 1.3 受影响文件与工作量

| 层 | 改动 |
|---|---|
| 后端 | `schemas.py`（`DashboardDeadlineItem` / `DashboardDeadlinesOutput`）、`cases.py`（`dashboard_deadlines` 只读查询）、`api/cases.py`（`GET /api/v1/dashboard/deadlines`）、重新生成 OpenAPI 与 `frontend/src/api/types.ts` |
| 前端 | `frontend/src/components/DeadlineTimeline.tsx`、`frontend/src/components/DeadlineTimeline.test.tsx`、`frontend/src/pages/CasesPage.tsx`、`frontend/src/workbench.css`、`frontend/src/api/endpoints.ts` |
| 测试 | `backend/tests/test_case_workbench.py` 补只读接口与归档过滤测试；前端 Vitest 组件测试 + Chromium/Safari 宽屏与 760px 半屏实测 |

粗估工作量：**1–2 个工作日**。无数据库迁移，验收通过后可直接应用。

### 1.4 验收条件

1. 时间轴显示的期限与各在办案件概览页完全一致（标题、日期、外部/内部、完成状态），已归档案件不出现。
2. 超过 50 个在办案件时，跨页案件的期限同样完整显示。
3. 逾期未完成标红；早于前 7 天仍未完成的期限显示在“更早逾期”区，不被截断。
4. 已完成期限默认隐藏，勾选后可见；窗口切换实时更新。
5. 点击任意期限卡片跳转到对应案件概览页。
6. 宽屏与 760px 半屏下均无重叠或不可读；Chromium 与 Safari 实测通过。

## 二、诉请金额构成（含分组与瀑布图）

> 架构说明（[D5](../decisions/20261120-主体关系图与证据目录模型.md)）：本项需要新增可写数据表，拆分为独立迁移 `0008_claim_amounts`，与主体关系图（`0007`）解耦。

### 2.1 场景

起草起诉状、变更诉请或核对判决金额时，将诉请按组拆分（例如“对被告一的诉请”“对被告二的连带诉请”“二审上诉请求”），每组内拆成本金、利息、违约金、费用与已付款抵扣，用瀑布图和明细表同步核对加总，并回溯每一项的计算说明和材料出处。

### 2.2 范围与业务规则

- **案件内多组诉请（Q2 已确认）**：
  - 每案可维护多组诉请（`claim_groups`，含名称、排序 `position`、币种默认 `CNY`、备注）。
  - 每组内含多条金额项（`claim_items`）：
    - 名称（≤200 字）；
    - 类别：`principal`（本金）/ `interest`（利息）/ `liquidated_damages`（违约金）/ `expense`（费用）/ `deduction`（抵扣）/ `other`（其他）；
    - 金额：`amount_cents`（`BIGINT >= 0`，精确到分，杜绝浮点误差）；`deduction` 类别在合计与瀑布图中自动按减项计算；
    - 计算说明（≤2000 字，如起止日期、利率、计算基数；首版纯文字，不做 LPR/分段利率自动计算）；
    - 出处（可选）：`segment_id`（`source_ref`）、`material_id` 或 `annotation_id` 三选一，可点击跳转 `SourcePreview`；
    - 排序 `position`。
- **从已抽取金额选取**：支持搜索并点选本案 `exact_values(kind='amount')` 候选值，一键带入金额（换算为分）与对应的 `segment_id` 出处，也支持纯手工录入。
- **展示**：
  - 每组一张 SVG 瀑布图 + 明细表，显示组内小计；抵扣项以向下柱条及负号呈现。
  - 页面顶部汇总本案全部诉请分组的总计（按币种分别汇总；若仅人民币则显示单一总额；若多组存在重叠加计语义如“一审/二审”，支持勾选“计入全案总计”开关默认开启，避免误加总）。
- **Agent 协同（Q3 原型默认开放，看原型时确认）**：Agent 可通过 MCP/CLI 提交候选分组或金额项，写入 `claim_changes` 并标为待确认（黄/绿徽标、确认/撤回），人工可确认或撤回；确认与撤回仅限人工入口。
- **归档与案件隔离**：案件归档后全部只读；跨案引用由 `(case_id, …)` 组合外键拒绝。

### 2.3 数据库设计草案：迁移 `0008_claim_amounts`

```sql
claim_groups(
  id uuid PK, case_id uuid NOT NULL → cases,
  title text NOT NULL (≤200),
  currency text NOT NULL DEFAULT 'CNY',
  include_in_total boolean NOT NULL DEFAULT true,
  position int NOT NULL DEFAULT 0,
  note text NULL (≤2000),
  created_by text CHECK IN ('human','agent'),
  updated_by text CHECK IN ('human','agent'),
  request_key text NULL, UNIQUE(case_id, request_key),
  removed_at timestamptz NULL, revision int NOT NULL DEFAULT 0,
  created_at, updated_at, UNIQUE(case_id, id))

claim_items(
  id uuid PK, case_id uuid NOT NULL → cases,
  group_id uuid NOT NULL → (case_id, claim_groups.id),
  title text NOT NULL (≤200),
  category text NOT NULL CHECK IN (
    'principal','interest','liquidated_damages','expense','deduction','other'),
  amount_cents bigint NOT NULL CHECK (amount_cents >= 0),
  calc_note text NULL (≤2000),
  segment_id uuid NULL → (case_id, segments.id),
  material_id uuid NULL → (case_id, materials.id),
  annotation_id uuid NULL → (case_id, annotations.id),
  position int NOT NULL DEFAULT 0,
  created_by text CHECK IN ('human','agent'),
  updated_by text CHECK IN ('human','agent'),
  request_key text NULL, UNIQUE(case_id, request_key),
  removed_at timestamptz NULL, revision int NOT NULL DEFAULT 0,
  created_at, updated_at,
  CHECK (num_nonnulls(segment_id, material_id, annotation_id) <= 1),
  UNIQUE(case_id, id))

claim_changes(
  -- 结构与 progress_changes 一致；复用 case_change_seq(case_id, 'claims')
)
```

> 审计闭集同步扩展 `claims.*` 操作名；一致性检查补充 `claim_items` 悬空出处与金额非负核对；备份恢复演练纳入 `0008` 新表。

### 2.4 服务、入口与前端模块

- **服务层（`backend/src/legal_workbench/claims.py`）**：
  - 读取：`get_claims(case_id)`（含各组小计、按币种全案总计、待确认变更、seq）、`list_amount_candidates(case_id, query=None)`（查 `exact_values(kind='amount')` 带出处摘要）。
  - 写命令（`begin_write` → 归档守卫 → `case_change_seq(case_id, 'claims') FOR UPDATE` → CAS → `claim_changes` → `seq+1` → 审计）：`add_group`、`update_group`、`reorder_groups`、`remove_group`、`add_item`、`update_item`、`reorder_items`、`remove_item`、`restore_item`。
  - 仅人工复核：`accept_claim_change`、`accept_all_claim_changes`、`revert_claim_change`。
- **入口**：HTTP `api/claims.py`（`GET/POST/PATCH/DELETE /api/v1/cases/{id}/claims/...`）；MCP & CLI 暴露查询、候选金额检索与分组/金额项增改删（不暴露确认/撤回）。
- **前端（`frontend/src/claims/`）**：
  - `types.ts`、`localExecutor.ts`、`httpExecutor.ts`、`fixtures.ts`（`TEST-ONLY` 合成案卷：两组诉请“对被告一主诉请”＋“二审变更诉请”、含本金/利息/违约金/律师费/已付款抵扣、模拟精确值选取与 1 条 Agent 待确认项）；
  - `WaterfallChart.tsx`（纯 SVG 瀑布图，正项向上、抵扣项向下、末柱为净合计，无新增图表依赖）；
  - `ClaimsPanel.tsx`（分组切换/总览、明细表与排序、金额项编辑 `<dialog>` 含输入法保护、精确值候选选择器、出处跳转 `SourcePreview`、Agent 待确认面板）；
  - P1 原型路由 `/prototype/claims`（首页虚线入口），P4 接入案件页新页签“诉请金额”。

### 2.6 诉请金额验收条件

1. 可新建、重命名、排序、删除诉请分组；组内可增改删排金额项，每组瀑布图柱高/起止位置与明细表小计完全一致。
2. 金额全程整数分计算，无浮点误差（如 `0.1 + 0.2` 与大额亿元级计算精确到分）；抵扣项按减法计入小计与总计。
3. 支持“计入全案总计”开关，多组（如一审/二审并存）不发生误重复加总。
4. 可从已抽取金额精确值中选取并自动带入 `segment_id` 出处；点击出处通过 `SourcePreview` 打开原文/原页。
5. 若 Q3 确认开放 Agent 提交：MCP 提交进入待确认，确认变绿、撤回还原，Agent 调用确认/撤回被拒。
6. 案件归档后全部只读；跨案引用被数据库拒绝；每个写命令有审计与变更记录；备份恢复后应用角色可读回全部数据。
7. Chromium 与 Safari 宽屏及 760px 半屏实测通过，中文输入法组词按回车不误提交。
